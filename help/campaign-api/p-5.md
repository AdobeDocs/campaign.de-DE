# Verwenden von Datumsangaben

In diesem Kapitel werden die Funktionen beschrieben, mit denen die Daten der auf dem Server ausgeführten JavaScript-Programme bearbeitet werden können (Workflow, JSSP usw.).

## Daten und Zeitzonen

In JavaScript werden Datumsangaben in UTC gespeichert. Dies bedeutet, dass Sie sich nur um Zeitzonen für die Datumserstellung oder die Konvertierung in Textzeichenfolgen für die interne Anzeige oder Speicherung kümmern müssen. Für die Datumskonvertierung gibt es zwei Funktionskategorien:

* die Funktionen der JavaScript-Bibliothek (date.toString(), date.toLocaleString(), date.getHours(), …),
* die Funktionen der Adobe Campaign-Plattform ( [formatDate(date, format)](f-formatdate.md) ).

Konventionell verwenden die Ersten die Zeitzone des Computers, während die Letzten je nach Kontext eine Zeitzone verwenden: in der Regel das des aktuellen Benutzers. Dieses Verhalten kann jedoch geändert werden, z. B. für Exporte oder Workflows.

## Aktuelles Datum abrufen

Es gibt zwei Möglichkeiten, das aktuelle Datum in JavaScript abzurufen:

* new Date() erstellt ein neues Date-Objekt, das mit dem aktuellen Datum initialisiert wurde. Das Datum fällt mit der Uhrzeit des Geräts zusammen, auf dem das Skript ausgeführt wird.
* [getCurrentDate()](f-getcurrentdate.md) Gibt das aktuelle Datum basierend auf der Zeit des Datenbankservers zurück.

Die Funktion [getCurrentDate()](f-getcurrentdate.md) ist der ersten Lösung vorzuziehen, insbesondere wenn das Datum mit anderen Daten aus der Datenbank verglichen oder in die Datenbank geschrieben werden soll. Diese Methode reduziert das Risiko von Diskrepanzen (bis zu mehreren Minuten) im Zusammenhang mit Zeitunterschieden zwischen dem Anwendungsserver und dem Datenbankserver

## Datumsangaben

Die Konvertierung eines Datums in eine Zeichenfolge zu Anzeigezwecken verwendet die Funktion [formatDate](f-formatdate.md).

## Konvertieren eines Datums aus einem XML-Dokument

Datumsangaben, die in einem XML-Dokument gespeichert sind, das aus der Adobe Campaign-Datenbank stammt, sind in Textform: Sie können mit der Funktion [parseTimeStamp](f-parsetimestamp.md) konvertiert werden. Dies betrifft normalerweise XML-Dokumente, die von der Methode [ExecuteQuery](sm-querydef-executequery.md) zurückgegeben werden. Beispiel :

```javascript
var query = NLWS.xtkQueryDef.create(
  {queryDef: {schema: "nms:delivery", operation: "get", 
    select: {
      node: {expr: "@lastModified"}
    }, 
    where: {
      condition: {expr: "@id=123456"}
    }
  }}
)

var delivery = query.ExecuteQuery()
var lastModified = parseTimeStamp(delivery.$lastModified)
```

## Einfügen eines Datums in ein XML-Dokument

Ob ein Datum in ein XML-Attribut geschrieben, ein Dokument gespeichert (Methode [Write](sm-session-write.md)) oder ein Literaldatum in den Ausdruck einer Abfrage eingefügt werden soll, das Datum muss in das ISO8601-Format konvertiert werden. In der Funktionsbibliothek xtk:shared/nl.js gibt es eine Methode zum Konvertieren eines Datums in dieses Format: die NL.XTK.formatDateTime(date)-Methode. Die Bibliothek kann mit der Funktion loadLibrary geladen werden:

```javascript
loadLibrary("xtk:shared/nl.js")
```

oder mithilfe der Seitenanweisung, falls es sich um eine dynamische JavaScript-Seite (JSSP) handelt:

```xml
<%@ page import="xtk:shared/nl.js" %>
```

Warnung: loadLibrary kann nicht für alle Skripte verwendet werden. Sie können beispielsweise keine Bibliothek mit JavaScript-Funktionen in einem E-Mail-Personalisierungsskript ändern. Beispiel : Dieses Beispiel zeigt die Erstellung einer Abfrage mit einem Literaldatum.

```javascript
loadLibrary("xtk:shared/nl.js")
NL.require('/nl/core/shared/xtk.js')
...

var date = ...

var query = NLWS.xtkQueryDef.create(
  {queryDef: {schema: "nms:delivery", operation: "select", 
    select: {
      node: {expr: "@id"}
    }, 
    where: {
      condition: {expr: "@lastModified > #" + NL.XTK.formatDateTime(date) + "#"}
    }
  }})

var result = query.ExecuteQuery()
```
