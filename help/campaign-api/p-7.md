# E4X-Migrationshandbuch

Die E4X-Erweiterung für die native Unterstützung von XML in JavaScript wird von Mozilla nach und nach aufgegeben. Adobe Campaign hat diese Erweiterung stark verwendet und bereitet sich daher auf die Migration zu einer alternativen Lösung vor.

Ziel dieses Handbuchs ist es, Sie durch eine Beschreibung der Ersatzlösungen bei der Migration vorhandener Konfigurationen oder der Entwicklung neuer Konfigurationen zu unterstützen.

Das alte und das neue System koexistieren, die aktuelle Version von Adobe Campaign ist immer mit E4X kompatibel, neue Konfigurationen dürfen jedoch nicht mit der E4X-Erweiterung entwickelt werden.

Erinnerung: E4X fügt einen Typ von JavaScript-XML hinzu, der direkt aus dem Quellprogramm erstellt werden kann:

```text
var doc = <xml> ... </xml>
```

oder aus einer Zeichenfolge:

```text
var doc = new XML ("<xml>...</xml>")
```

Sie kann dann mit einer bestimmten API bearbeitet werden:

```text
element.@id element.where
```

## XML-Typ

Der native Typ „xml“ wird durch eine DOM-API ersetzt. Dies sind [DOMDocument](c-domdocument.md) , [DOMElement](c-domelement.md) , [DOMNode](c-domnode.md) Typen, … Folgendes entspricht den gängigsten Vorgängen:

> **E4X:**
>
> ```javascript
> anElement.@id
> ```
>
> **DOM:**
>
> ```javascript
> anElement.$id
> ```
>
> **E4X:**
>
> ```javascript
> anElement.@["recipient-id"]
> ```
>
> **DOM:**
>
> ```javascript
> anElement["$recipient-id"]
> ```
>
> **E4X:**
>
> ```javascript
> anElement.childElement
> ```
>
> **DOM:**
>
> ```javascript
> anElement.getElements("childElement")
> ```
>
> oder
>
> ```javascript
> anElement.getFirstElement("childElement")
> ```

XML-Dokumente in einer JavaScript müssen ersetzt werden. Wenn dieses Dokument für eine native Funktion oder einen SOAP-Aufruf verwendet werden soll, der ein XML-Dokument als Parameter übergibt, können Sie ein JSON direkt übergeben. Dieser wird automatisch in ein XML-Dokument (DOMDocument) umgewandelt. Andernfalls können Sie immer über ein JXON-Objekt übergeben. Es ist jedoch eine explizite Konvertierung mit der Funktion [DOMDocument.fromJXON](m-domdocument-fromjxon.md) erforderlich.

```javascript
var doc = DOMDocument.fromJXON({queryDef: 
{schema: "xtk:workflow", operation: "select",
  select: { node: {expr: "@internalName"} } 
}
})
```

Beispiel für die Gleichwertigkeit von XML- und JSON-Syntax:

> **E4X:**
>
> ```xml
>                             <queryDef schema="nms:delivery" operation="get">
>     <select>
>         <node expr="@created"/>
>         <node expr="@lastModified"/>
>     </select>
>     <where>
>         <condition expr="@id=123456"/>
>     </where>
> </queryDef>
> ```
>
> **JXON:**
>
> ```javascript
>                             {queryDef: {schema: "nms:delivery", operation: "get", 
>     select: {
>         node: [
>             {expr: "@created"}, 
>             {expr: "@lastModified"}]
>         }, 
>     where: {
>         condition: {expr: "@id=123456"}
>     }
> }}
> ```

Weitere Informationen zur JSON-Syntax finden Sie auf der Seite Verwenden von XML .

## SOAP-Aufrufe

Diese SOAP-Methoden müssen NLWS-Objekteigenschaften ausführen. Die JavaScript-ID des Schemas wird aus dem Namespace und dem Namen erstellt, die mit einem Großbuchstaben beginnen. Das Schema nms:delivery hat beispielsweise nmsDelivery als JS-ID.

> **alt:**
>
> ```javascript
> nms.delivery.Play(deliveryId);
> ```
>
> **Neu:**
>
> ```javascript
> NLWS.nmsDelivery.Play(deliveryId);
> ```

## SOAP JavaScript-Methoden

Um ein XML-Dokument zu erhalten, dessen Parameter im DOM-Format und nicht im E4X-Format vorliegen, muss dem Schema das Attribut dom=„true“ hinzugefügt werden.

## Mehrzeilige Zeichenfolgen

Die Verwendung von XML zum Erstellen mehrzeiliger Zeichenfolgen muss durch eine Verkettung von Zeichenfolgen ersetzt werden, indem vergessen wird, das Ende der Zeile \\n hinzuzufügen.

> **alt:**
>
> ```xml
> <str>line 1
> line 2
> line 3
> </str>.toString()
> ```
>
> **Neu:**
>
> ```javascript
> "line 1\n" +
> "line 2\n" +
> "line 3\n"
> ```

## Content-Management

Es ist erforderlich, die DOM-Option in der Veröffentlichungsvorlage oder in der JavaScript-Vorlage während der Vorschau zu aktivieren. Für eine XSL-Transformation mit JavaScript-Vorverarbeitung müssen Sie auch die DOM-Option aktivieren (Aggregator-Fenster).
